# Правила оформления коммитов

Этот проект использует [Conventional Commits](https://www.conventionalcommits.org/) для стандартизации сообщений коммитов.

## Формат коммита

```
<тип>(<область>): <описание>

[необязательное тело]

[необязательный футер]
```

### Примеры

```bash
feat(curriculum): добавить урок «Объекты конфигурации»
fix(frontend): исправить переход к следующему шагу урока
docs: обновить правила коммитов
style(frontend): выровнять отступы в карточках модуля
refactor(generator): вынести сборку тем в CourseBuilder
test(frontend): добавить тесты для ProgressStore
```

## Типы коммитов

### `feat` - Новая функциональность

Новая возможность приложения или новый учебный контент.

```bash
feat(curriculum): добавить урок «Справочники и документы»
feat(frontend): добавить модалку темы
```

### `fix` - Исправление бага

Исправление ошибки в коде или фактической ошибки в уроке.

```bash
fix(curriculum): исправить пример запроса в шаге про регистры
fix(frontend): исправить сохранение прогресса после перезагрузки
```

### `docs` - Документация

Изменения только в документации проекта (`docs/`, README).

```bash
docs: добавить правила коммитов
docs(readme): описать запуск проекта
```

### `style` - Стиль кода

Изменения, не влияющие на логику (форматирование, пробелы, точки с запятой).

```bash
style(frontend): исправить отступы в компонентах
style(curriculum): выровнять таблицы в уроке
```

### `refactor` - Рефакторинг

Изменение кода без добавления функций или исправления багов.

```bash
refactor(frontend): разделить LessonReader на виджет и фичу
refactor(generator): упростить чтение шагов урока
```

### `perf` - Производительность

Изменения, улучшающие производительность.

```bash
perf(frontend): загружать шаги урока лениво
```

### `test` - Тесты

Добавление или изменение тестов.

```bash
test(frontend): добавить тесты для хука прогресса
test(generator): покрыть тестами проверку нумерации шагов
```

### `build` - Сборка

Изменения в системе сборки или зависимостях.

```bash
build(deps): обновить next до 16.5
build: добавить алиас @curriculum
```

### `ci` - CI/CD

Изменения в конфигурации CI.

```bash
ci: добавить GitHub Actions для проверок
```

### `chore` - Рутинные задачи

Другие изменения, не затрагивающие код приложения, уроки и тесты.

```bash
chore: обновить .gitignore
chore(config): поправить настройки ESLint
```

### `revert` - Откат

Откат предыдущего коммита.

```bash
revert: откатить "feat(curriculum): добавить урок «Регистры»"
```

## Область (scope)

Область указывает, какая часть проекта затронута:

- `curriculum` - уроки, темы, модули (`curriculum/`)
- `frontend` - Next.js-приложение (`frontend/src/`)
- `generator` - генератор курса (`frontend/scripts/course/`)
- `deps` - изменения зависимостей
- `config` - изменения конфигурации (ESLint, TypeScript, Next, Vitest)

Область необязательна, но рекомендуется.

## Описание (subject)

- Используйте повелительное наклонение: "добавить" вместо "добавил"
- Не ставьте точку в конце
- Максимум 100 символов
- Начинайте с маленькой буквы (после двоеточия)

### ✅ Хорошо

```bash
feat(curriculum): добавить урок «Типы данных»
fix(frontend): исправить ошибку при открытии модалки
```

### ❌ Плохо

```bash
feat: Добавил урок.
fix: исправление ошибки
```

## Тело коммита (body)

Необязательное подробное описание изменений:

```bash
feat(frontend): добавить прогресс по модулям на главной

Прогресс считается по пройденным урокам из ProgressStore.
Добавлен компонент ModuleProgress.
Обновлены тексты в COURSE_TEXT.
```

## Футер (footer)

Используется для ссылок на issue или breaking changes:

```bash
fix(frontend): исправить кнопку «К следующему уроку»

Closes #12
```

```bash
refactor(generator): изменить формат topic.json

BREAKING CHANGE: список уроков теперь хранится в поле lessons вместо titles
```

## Проверки перед коммитом

Автоматических хуков пока нет, проверки запускаются вручную:

```bash
# Пересобрать карту курса и загрузчики шагов
pnpm --dir frontend course:generate

# Проверка типов
pnpm --dir frontend typecheck

# Линтинг
pnpm --dir frontend lint

# Тесты
pnpm --dir frontend test

# Сборка
pnpm --dir frontend build
```

Если сообщение коммита оформлено неверно, исправьте его:

```bash
git commit --amend -m "feat(curriculum): добавить урок «Типы данных»"
```

## Примеры хороших коммитов

```bash
# Простой коммит
feat(curriculum): добавить урок «Переменные и выражения»

# С телом
fix(frontend): исправить мигание модалки модуля

Модалка открывалась повторно при возврате назад,
потому что Next держал прошлый роут в Activity.
Добавлено закрытие dialog при скрытии роута.

# С breaking change
refactor(generator): изменить структуру module.json

BREAKING CHANGE: поле hours переименовано в durationHours

# С закрытием issue
fix(curriculum): исправить пример кода в шаге про условия

Closes #7

# Множественные изменения
refactor(frontend): улучшить структуру слайса lesson

- Вынести тексты в LESSON_READER_TEXT
- Разделить хук прогресса на чтение и запись
- Убрать относительные импорты
```
